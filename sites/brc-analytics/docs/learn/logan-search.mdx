## What it is

[Logan](https://github.com/IndexThePlanet/Logan) is an assembly of nearly every public run in the NCBI Sequence Read Archive (SRA) up to the end of 2023: tens of millions of runs, each reduced to its assembled contigs. Those contigs are indexed with [kmindex](https://github.com/tlemane/kmindex), which can tell you, for a short query sequence, which runs share a large enough fraction of its k-mers.

[Logan Search](https://logan-search.org) runs that lookup for you. Paste a sequence (a gene, a marker, a stretch of a pathogen genome), pick which parts of the archive to search, and you get back the SRA runs it occurs in, ranked by how much of the query each one contains. Searches are queued as jobs — a typical one finishes in a few minutes — and the results page can be left and reopened.

## Your query

- **One sequence per query**, as FASTA, FASTQ or bare bases. Compressed formats such as `.fastq.gz` aren't supported yet; unzip them first.
- **Keep it gene-sized.** Logan's index is built for gene-sized queries — a few thousand bases, not whole genomes.

## Threshold

The threshold is the minimum fraction of the query's k-mers a run must contain to count as a hit; it defaults to 0.5. Lower values return more runs and take longer; below about a quarter the hit list is mostly noise.

A longer query isn't a more specific one. The score is the fraction of the query's k-mers a run shares, so extending a query into conserved flanking sequence raises that fraction in unrelated runs too. In one test, a 2,090-base 18S query matched more runs than the 500-base window inside it. To narrow a search, raise the threshold or pick a less conserved stretch of sequence.

## What gets searched

The archive is split into indexes by organism group and library type — genomic bacteria, metatranscriptomes from environmental samples, and so on. You choose which parts of the archive to search. Named groups cover the common cases: **All**, **All but viral and human**, **Transcriptomic**, **Metatranscriptomic**, **Metagenomic**, and the **GenBank/RefSeq** reference genomes.

Searching more of the archive costs more, so restricting the search to where your query plausibly lives is faster.

## Reading the scores

- **k-mer coverage** is the fraction of the query's k-mers found in a run. A small set of runs (227 of them) have indexes so saturated that they report a share of any query's k-mers whether or not the sequence is there. For those, a baseline is subtracted, and a hit that falls below the threshold after that correction is dropped.
- **ANI est.** is an estimate of average nucleotide identity between the query and what's in the run, computed as coverage^(1/31) (k = 31). A coverage of 0.94 is an ANI of about 0.998. It's an estimate from k-mer sharing, not an alignment.

## Results

The results list the runs your query matched, ranked by coverage, with each run's SRA accession and metadata. For any hit you can align your query against that run's assembled contigs to see where it lands. You can leave an email address to be notified when a long search finishes, and each search produces a results page you can bookmark or share.

## Relationship to BRC Analytics

Logan Search runs on BRC Analytics and Galaxy infrastructure: searches submitted on logan-search.org go through the BRC Analytics API, which runs the kmindex lookups as jobs on usegalaxy.org. The BRC Analytics and Logan teams are also collaborating to bring a new UI to logan-search.org, and — through BRC Analytics' partnership with TACC — to deploy the updated Logan v1.2 index, which covers the December 2025 freeze of the SRA (87 petabases across 38 million accessions).
