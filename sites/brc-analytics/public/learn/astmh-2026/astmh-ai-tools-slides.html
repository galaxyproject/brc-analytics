What the Trail Actually Caught

Zoom in on those ribbons — every fork is a silent, consequential choice.

The wrong-organism ribbon
One plan's "B. cereus ATCC 10987" was actually Salmonella SC-B67 (GCF_000008105.1) — a mislabeled accession. And between valid assemblies: anQ-h4 lacks the cytK2 toxin locus entirely, so the toxin reads "undetected" vs. actively transcribed.
The tool-stack splinter
Engines ranged from custom Nextflow to ad-hoc Bash/R; aligners split HISAT2 / Bowtie2 / Kallisto; rRNA handling diverged on SortMeRNA. Four plans silently reversed library strandedness — real transcripts miscounted.
The major fork: model scope
18 plans analyzed only the 5 target replicates; the rest — including all 10 Claude plans — pooled all 19 libraries to estimate variance. Same data, different statistical power, different DEG calls.
Evidence

Two Failure Modes, Two Guardrails

The splintering isn't random — each failure mode maps to a mitigation.

Failure modes
Guardrails
Consistency

Faced with ambiguous choices, agents diverge — same dataset, 18 incompatible pipelines.

BRC Analytics + GTN

Strong curation — curated organisms, assemblies, vetted workflows, and training materials, so the agent starts on checked ground.

Traceability

Disposable local scripts — no record of versions, parameters, or steps. Nothing to check, nothing to rerun.

Galaxy

Execution on public infrastructure — every action provenance-tracked, every run shareable and auditable.

Motivation
Two identifiable failure modes → two mitigations. Consistency under ambiguity is a curation problem — that's BRC Analytics. Traceability is an infrastructure problem — that's Galaxy's 20 years of provenance-tracked execution. This is the middle ground: don't fight adoption, route the work where the record lives.

MCP — Two Servers: What vs Where

BRC MCP — what to run
brc-analytics.org/api/v1/mcp
Public endpoint, no auth. Catalog tools (organisms, assemblies, workflows) + ENA sequencing search — the curation layer, exposed as tools.
Galaxy MCP — where to run it
uvx galaxy-mcp · galaxyproject/galaxy-mcp
Installable server that connects your client to a Galaxy instance — executes tools and workflows on real Galaxy; history keeps the record.
Why it matters
  • The guardrail: the agent sees curated answers — e.g. which workflows fit which assemblies — not raw tools it improvises around
  • Works with Claude Code, Codex, Antigravity — any MCP client, your own scripts, a local model on university HPC. We don't pick your AI for you

Orbit — Agentic Workbench with a Paper Trail

How it works
  • Install it locally — point it at any OpenAI- or Anthropic-compatible API
  • Human gate at each step — the agent drafts plans and parameters; you approve and review before anything runs on Galaxy
  • notebook.md + git = the record — a provenance trail, not a chat log
The guardrail
  • Missing tool → agent authors a reviewable User-Defined Tool beta instead of silently improvising locally
  • Export → gxformat2 → PR to iwc-lab — the workflow outlives the session
